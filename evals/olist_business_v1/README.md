# 巴西电商 Agent 业务场景测试集 v1

小城，这套材料用于以后考察你的数据分析 Agent：**只制作题目和评分依据，本轮未向 Agent 出题、未运行 Agent 评测、未修改应用。** 空白评分表所有题目均为“未测试”。

64 道场景题，覆盖从理解数据、经营诊断到预测和管理交付的 13 个模块。每题有可直接复制的问法、五项最低要求、不能接受的关键错误，以及失败后该检查哪类能力。题目不是要求背固定答案；有执行证据、方法正确且符合业务含义的等价回答都可接受。

## 给 Agent 的共同约定

“仅题目.md”已包含以下约定，出题时一并给出：

1. 使用完整九表；若未接入全量，先说清实际可访问范围，不假装已经使用全量。
2. 除题目另说，经营金额分析用源快照中 `order_status='delivered'` 的订单，按下单时间归期。订单状态分布、全部下单预测另按题意使用全订单。
3. 商品金额为明细 `price` 之和、不含运费；运费与支付金额单列。金额不是平台收入或利润。
4. 客户跨订单识别用 `customer_unique_id`。订单评价按 `review_answer_timestamp`、`review_creation_date`、`review_id` 依次降序取首条；缺排序字段置后，仍完全并列且评分冲突时要披露并制定规则。
5. 延迟按签收日大于预计送达日，同日不迟到；低评分为 1–2 分。缺日期或评分按用途排除并报告分母，不补零。
6. 日期保持源时间，不自行改为北京时间或 UTC；日期区间边界写明。所有结果属于历史回看，若要求“当时可知”，必须防止使用未来信息。
7. 金额需精确到分，浮点边界不作为资金异常依据。无记录、未知、零和不适用需要区分。
8. 需要计算的题要实际执行并提供可复核结果；无法执行要直说。数据缺口题应说明缺口并提供有用的下一步，不编造数字。

口径已在题面给定时，不强迫 Agent 重复询问。B62 特意只给模糊首轮，用于观察它是否会先澄清关键问题。

## 以后如何出题和评分

1. **单题独立场景**：B01–B60 默认新聊天，绑定相同全量数据；不要让前题答案自动成为后题提示。保持模型/工具/数据版本等条件可比。
2. **多轮场景**：B61–B64 在同一聊天依次发各轮，等一轮结束再发下一轮；不要一开始透露后续纠正。B63 的 SQL 使用概念表名，实际映射应由 Agent 检查。
3. **保留首次回答**：记录原始输出、实际执行结果、图表/文件和错误，不用人工纠正后的答案覆盖首轮。纠正后成功另记“人工提示后通过”。
4. **逐项评分**：每题五项，各 0–2 分；0=缺失或错误，1=方向正确但未完成/缺证据，2=完成且可复核。达到最低标准需总分≥8、每项≥1、无本题关键错误。
5. **区分两种核验**：有数字参考的部分核对计算；无完整数值参考的探索/统计/建模结果，需按原始数据独立复核，不能只看文风或让同一个模型自评。图表和文件题另查实际可用性。
6. **定位再改动**：记录最早出错环节和修改建议，修改后复测原题，再更换时间/地区/表达做迁移验证。原题已用于调试后，不再称独立盲测。

建议评分规则是本测试集的操作约定，不是行业认证分数。64 题总分上限 640，但总分不能抵消资金算错、使用未来信息或编造结果。模块之间分开看“首次独立通过数/已测题数”和关键错误，未测试题不当 0 分也不算通过。

若某题当前产品不支持交互看板、文本分析或建模，应记“能力缺口”，并保留未完成项；不要换成纯文字方法就认定该业务能力通过。B54 允许在缺预测时只做设计；记录为“方案达标、实测未完成”，不能据此认定模型有效。

不以关键词匹配、固定排版、用了多少图/代码来判整体质量；满足题目明确要求即可。合理替代方法可以得分，但改了口径就不能继续拿原数值做一致性判断。

### 容差与证据

- 实体/订单/条目数应精确一致；整数分金额应精确一致。按 BRL 展示四舍五入至两位时，按同一舍入规则比较，不用“大致接近”放过重复计数。
- 表示为百分比的小数位不同，可以按显示精度核对；必须检查原始分子分母，不能以大容差掩盖错分母。
- 对称分解的两个效应用未舍入值核对，显示四舍五入产生一分钱差异可解释。其他闭合分解允许，但要说明公式，不能强套对称数值。
- 总体事实锚点已重算，三项重要金额另用标准库 CSV+Decimal 独立求和交叉核对；哈希、键唯一性和加总检查在脚本中。
- **尚无全部 64 题的完整标准解**：共购、地理距离、文本、统计区间、留存矩阵、模型与预测等，当前提供的是最低方法/交付标准，未声称本轮全部实际运行过。不能将这些题仅凭数值文件自动判分。

## 失败后优先改哪里

| 观察到的失败 | 先检查的环节 | 典型题 |
|---|---|---|
| 业务实体或问题理解错 | 数据字典、字段语义、关键澄清 | B01/B26/B62 |
| 数字重复、订单丢失 | 关联基数、汇总粒度、左关联覆盖 | B03/B16/B36/B63 |
| 钱对不上、阈值一分钱出错 | 金额类型、未知覆盖、比较算子 | B36/B38 |
| 比例结论失真 | 分母、去重客户、权重、样本成熟度 | B21/B23/B24/B41 |
| 把尾月当衰退、历史名单含未来 | 数据截止、可见时间、快照限制 | B12/B22/B34/B51 |
| 统计/模型看似高级却无用 | 混杂、效果大小、基线、时间回测 | B46/B47/B50/B51/B55 |
| 缺数据也硬编利润或因果 | 可回答性判断、指标命名、证据限制 | B35/B53/B56–B60 |
| 改口径后图文或导出还是旧的 | 会话状态、依赖更新、产物绑定 | B10/B61/B64 |
| 只讲方法、没有真实执行 | 工具执行、错误恢复、证据持久化 | B06/B51/B63/B64 |

先修影响可信度的根因，再改善表达。能正确承认不够数据、纠正用户错误前提、如实汇报弱模型，都是应当奖励的能力。

## 本轮交付边界

本轮只有测试集编制和参考答案准备，没有执行任何被测 Agent 题目，没有产生 Agent 评分，没有修改模型、提示词、应用代码或现有聊天。题库公开后用于开发调试更合适；要做真正留出验收，后续另换窗口/实体/问法并隔离答案，不能以本套反复调试成绩冒充独立能力。

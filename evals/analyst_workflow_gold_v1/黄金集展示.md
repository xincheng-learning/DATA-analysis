# 从业务数据到可复核成果：分析师工作流黄金集

这套黄金集以数据分析师日常接到的业务任务为起点，观察 Agent 能否协助完成经营分析、口径确认、数据准备、清洗对照、连续追问和成果交付。

它包含 **3套合成数据、8个业务任务、20条顺序交互**。每项任务既有可核对的数值，也有明确的交付要求：使用什么数据、哪些条件经过确认、哪些部分存在缺口、修改条件后哪些结果需要重新计算。

> 当前状态：21组标准结果交叉核对及6项黄金集自检通过。首轮真实Agent测试已完成，完整业务任务0/8通过；部分准备、确认和清洗环节有效。失败原因与证据见[首轮实测报告](../../docs/分析师黄金集首轮实测-2026-11-16.md)。

## 先导入什么数据？

三套数据分别用于不同任务，每个任务在独立会话中导入对应目录的全部 CSV。无需把三套数据混在一起，也不要上传参考答案。

| 数据集 | 导入文件 | 数据规模 | 对应任务 |
| --- | --- | --- | --- |
| 经营订单数据 | `commerce/`中的4张表 | 18笔订单、23条商品明细、7条退款、12条目标 | A01—A05、A07 |
| 新增订单批次 | `dirty/orders.csv` | 7笔订单 | A06 |
| 不完整销售日报 | `presentation/daily_sales.csv` | 8条日×地区×渠道记录 | A08 |

这些是用于复核分析过程的小规模合成样本，不是真实企业经营数据，也不是大表性能测试。部分经营记录复用项目已有开发集，新增批次和日报数据为本版补充；本集不作为独立盲测宣传。

### 1. 经营订单数据：从四张表理解一门生意

订单发生在2026年1—4月，包含已完成和取消订单，覆盖华东、华南、华北，以及线上和门店两个渠道，金额单位为人民币元。目标表另含一条5月目标，不能把目标月份当成实际订单覆盖月份。

| 文件 | 一行代表什么 | 主要字段 | 可以回答什么 |
| --- | --- | --- | --- |
| [orders.csv](data/commerce/orders.csv) | 一笔订单 | 订单号、下单日期、客户、地区、渠道、状态、运费 | 订单量、期间与渠道范围 |
| [items.csv](data/commerce/items.csv) | 一条商品明细 | 明细号、订单号、商品、数量、成交单价 | 商品销售额、订单金额 |
| [refunds.csv](data/commerce/refunds.csv) | 一笔退款事件 | 退款号、订单号、金额、状态 | 已结退款、退款后金额 |
| [targets.csv](data/commerce/targets.csv) | 一个月×地区的目标 | 月份、地区、目标金额 | 实际与目标比较 |

例如，订单 `O01` 有两条商品明细：

| 订单 | 商品 | 数量 | 单价（元） | 商品金额（元） |
| --- | --- | ---: | ---: | ---: |
| O01 | A | 2 | 100 | 200 |
| O01 | B | 1 | 50 | 50 |

这是一笔订单、两条明细，商品金额为250元；订单表另记录8元运费。它还发生了两笔已结退款，分别为30元和20元。因此，商品金额、含运费金额和退款后商品金额是不同的业务口径，需要按任务约定使用。

订单和明细、退款通过订单号关联；地区目标按月份与地区匹配。明细和退款都可能一单多条，目标也不能随明细行重复累加。

这套数据没有成本、税费和经营费用，所以可以核对商品销售及退款，不能据此计算完整净利润。退款表没有结算日期，只能按原订单期间归属，不能分析现金退款实际发生月份。

### 2. 新增订单批次：数据有问题时，分析如何继续？

[新增批次](data/dirty/orders.csv)含7笔订单，金额已经是整笔商品金额。其中保留了几种常见情况：

| 记录 | 原始情况 | 分析时需要考虑什么 |
| --- | --- | --- |
| D02 | 状态文本为 ` completed `，两端有空格 | 是否授权统一状态，从而改变纳入范围 |
| D03 | 日期为 `bad-date`，金额200元 | 无法判断属于哪个月，不能猜测日期 |
| D04 | 金额为空 | 未知金额不能补成0 |
| D07 | 金额明确为0 | 零金额是有效记录，不能当缺失删除 |

批次还包含取消订单和次月订单。任务要求 Agent 先说明这些问题对本轮分析的影响，再由分析师决定是否清洗；预览、实际应用和撤销应有清楚区别。

### 3. 不完整销售日报：图表不能掩盖数据缺口

[日报摘录](data/presentation/daily_sales.csv)覆盖2026年2月1—5日的报告窗口，包含两个较长的地区名称及线上、门店两个互斥渠道。

- 2月3日没有任何记录，不表示当天销售额为0。
- 两个已记录单元的金额未知，不能用其他单元的金额补齐。
- 2月4日线上金额明确为0，应与未知区分。

Agent 需要在表格、图表和导出中一致表达这些差异；已知金额合计可以汇报，但不能包装成完整业务销售额。

## 黄金集包含哪些业务任务？

以下按真实使用顺序展示问题。确认和追问由分析师逐轮发出，不能把后续答复提前放进首轮提示。

除A01需要先确认销售定义外，经营数据任务已给定共同口径：仅统计已完成订单；商品销售额不含运费，退款单列；只扣已结退款；订单按订单号去重；客单价为销售额除订单数；期间按下单自然月。已明确的口径无需重复询问。

### A01｜制作月度经营简报

**业务背景：** 经营负责人需要复核2月表现，销售额是否含运费、是否扣退款尚未确认。

1. **提出任务：**「整理2月份经营简报：销售额、订单数、客单价和每日走势，给我可核对的表和图。」
2. **确认口径：**「确认：只看已完成订单；销售额按商品成交金额，不含运费，退款单列；订单去重，客单价用销售额除订单数。按下单自然月，未知不补零。请继续。」
3. **继续追问：**「只看线上渠道，其他条件不变，更新这份简报。」

**验收重点：** 关键口径先建议、后确认；确认后覆盖指标与图表；渠道变化后重新计算，不借用旧图。

### A02｜解释经营环比变化

**业务背景：** 分析师要先弄清数字怎样变化，再决定是否深入调查经营原因。

1. 「比较2026年2月与1月销售额，差了多少、变化百分比是多少？从订单量和客单价解释数字变化，先不猜经营原因。」
2. 「再按渠道拆开两月销售变化，哪些增加、哪些减少？它们与整体差额能否对上？」

**验收重点：** 期间和分母一致，分解能够对账；算术贡献与经营因果分开，不要求唯一的解释措辞。

### A03｜复盘地区目标完成情况

**业务背景：** 会议需要一份地区实际、目标与差额的比较材料；部分地区没有目标，另有地区目标明确为0。

1. 「整理2026年4月各地区销售额、目标、实际减目标的差额和完成率，按销售额排名作图，方便开会跟进。」
2. 「哪些地区可以判断目标完成情况，哪些不能？给出对应依据，保留未能判断的地区。」

**验收重点：** 目标不重复累加；缺目标和目标为0分开处理；不能计算的完成率保持未定义，仍保留实际销售。

### A04｜复盘客户复购并调整渠道归属

**业务背景：** 复购定义为一季度内至少两笔已完成订单。首轮按订单渠道分别统计，同一客户可能进入不同渠道。

1. 「复盘一季度购买客户和复购客户：整体有多少、复购率是多少？各渠道分别怎样？说明渠道人数能不能相加。」
2. 「现在每位客户只归属一个渠道，按该客户在当前导入数据中首笔已完成订单的渠道归属。重算渠道复购，其他条件不变。」

**验收重点：** 客户、订单和明细粒度分开；两种归属定义采用各自正确的分母；导入数据内首购不扩大为客户终身首购。

### A05｜完成退款对账，说明利润资料缺口

**业务背景：** 财务需要可核对的销售与退款数据，但成本和费用暂时无法提供。

1. 「给我2026年2月商品销售、已结退款和退款后金额，顺便判断净利润能否算；资料不足的部分列清楚，其他部分继续。」
2. 「成本和费用暂时补不了，先沿用上述口径，按地区列出这三项金额，不再等待利润资料。」

**验收重点：** 一单多退款正确汇总，排除未结退款；不把退款后商品金额称为净利润，也不因利润资料不足拒绝所有分析。

### A06｜评估新增数据，预览清洗并撤销

**业务背景：** 新批次存在日期、状态和金额问题。当前只看可识别为2月的已完成订单，未知不补零，尚未授权修改数据。

1. 「先判断这批订单能否支持2月份销售分析，有哪些影响结果的问题？不要修改数据。给我处理建议和影响。」
2. 「同意把状态两端空格作为待处理方案，其他内容保持原样；先只预览，不应用。按可识别二月且状态精确匹配的同一口径，对照处理前后的金额与样本；未知不要补零。」
3. 「确认应用刚才预览的状态去空格方案，别改日期或金额。复核实际新版本并保留原数据。」
4. 「撤销刚才的清洗，回到原批次版本，告诉我哪些数字和图需要重新计算。」

**验收重点：** 自动准备与人工授权衔接；预览不改正式数据；实际版本与预览复核；撤销可追溯。若对照不支持，必须明确未核验，不能编造差额或算作该能力已通过。

### A07｜在会议中连续修改分析条件

**业务背景：** 分析师需要连续切换月份和指标，已有的其他口径继续沿用。

1. 「先列2026年2月各地区商品销售额，给我比较图。」
2. 「改看1月，其他条件不变。」
3. 「仍看1月，改成扣掉已结退款后的金额，更新表和图。」

**验收重点：** 每轮使用正确的新条件；旧数字与图保留原适用范围；不能把上一轮成功结果冒充本轮重算结果。

### A08｜交付不完整日报的图表与导出

**业务背景：** 分析师要整理五天日报，只汇报摘录内已知金额，并保留数据缺口。

1. 「整理这五天销售日报：每天已知金额和地区表现都要有表和图。缺失保留，长地区名称可读，坐标注明日期和元，方便我核对。」
2. 「现在只看线上，其他条件不变。更新逐日图，并导出与这张图同范围的五天明细，未知不要写成0。」

**验收重点：** 日期、单位和长标签可读；没有记录、未知和0保持区别；表、图及实际下载内容使用同一范围。

## 怎样判断任务完成？

验收沿着分析师工作流记录证据，不只检查最终数字。

| 环节 | 需要看到的证据 |
| --- | --- |
| 需求覆盖 | 用户要求的指标、比较、图和导出都有回应，缺口明确 |
| 数据准备 | 检查针对本轮问题，说明可用范围及限制 |
| 人工决定 | 需要时给建议、理由和影响，获得确认；已有明确条件不反复问 |
| 数据与计算 | 使用获准的版本、期间、口径和粒度，结果可复核 |
| 清洗影响 | 适用时有预览、授权、前后差异和原版本依据 |
| 交付与接续 | 图表及导出一致，旧结果失效可识别，失败不冒充完成 |

每个适用项分别记录通过、失败或待人工判断；不适用项单独注明。错误数字、未经授权改变数据、未知补零造成失真、旧结果冒充新结果等关键错误，不能用其他环节的分数抵消。

合理的替代SQL、列名和图型可以接受。资料确实不足时，准确的部分完成可以通过相应边界检查，但不能据此宣称未完成的计算或交付已经通过。

## 标准答案从哪里来？

答案与Agent执行分开准备：先从原始记录独立计算，再执行参考SQL交叉核对。标准不根据Agent本轮回答临时修改，也不把参考答案、参考SQL和后续人工答复提前发送给Agent。

部分对账锚点如下：

| 检查项 | 参考结果 |
| --- | --- |
| 2月商品销售额、订单数、客单价 | 590元、4笔、147.5元 |
| 2月相对1月销售差额 | -125元 |
| 2月已结退款、退款后商品金额 | 50元、540元 |
| 状态去空格前后：纳入订单数 | 3笔 → 4笔 |
| 状态去空格前后：已知金额 | 100元 → 150元，未知金额仍有1笔 |

完整参考结果见[标准答案](标准答案.md)，逐项依据见[验收规则](验收规则.md)。表中是标准值，不是Agent实测输出；例如A05实测返回销售额8元，而标准为590元，故判关键错算。
